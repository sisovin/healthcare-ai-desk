# M2.3 — Agent-to-Project Assignment Workflows

## Objective
Deliver organization-safe agent assignment workflows using `agent_project_assignments`.

## Deliverables
1. Assignment APIs:
   - assign agent to project
   - list assignments (by agent / by project)
   - remove assignment
2. Conflict handling:
   - prevent duplicate assignment rows
   - explicit conflict response on duplicate attempts
3. Ownership integrity:
   - agent and project must belong to same organization
   - assignment actor recorded when available

## Proposed endpoints
- `POST /api/v1/agents/{agent_id}/projects/{project_id}`
- `GET /api/v1/agents/{agent_id}/projects`
- `GET /api/v1/projects/{project_id}/agents`
- `DELETE /api/v1/agents/{agent_id}/projects/{project_id}`

## RBAC requirements
- `agent.read`: list assignment views
- `agent.assign`: create/delete assignment

## Acceptance criteria
- Cross-organization assignment attempt fails with `403` or `404`.
- Duplicate assignment attempt returns `409`.
- Deleting assignment is idempotent and auditable.
