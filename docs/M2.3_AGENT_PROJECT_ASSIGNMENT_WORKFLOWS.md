# M2.3 — Agent Runtime & Execution Engine

## Objective
Deliver organization-scoped runtime execution capabilities based on published agent versions, with lifecycle control, task queueing, audit logs, and human approval.

## Implementation package

### 1) Published Versioning
- Table: `agent_versions`
- API:
  - `POST /api/v1/agent-runtime/agents/{agent_id}/versions/publish`
  - `GET /api/v1/agent-runtime/agents/{agent_id}/versions`
- Behavior:
  - snapshot agent configuration at publish time
  - monotonic `version_number` per `(organization_id, agent_profile_id)`

### 2) Execution Lifecycle
- Table: `agent_executions`
- API:
  - `POST /api/v1/agent-runtime/agents/{agent_id}/executions`
  - `GET /api/v1/agent-runtime/executions/{execution_id}`
  - `PATCH /api/v1/agent-runtime/executions/{execution_id}/status`
- Status set:
  - `queued`, `running`, `waiting_approval`, `completed`, `failed`, `cancelled`

### 3) Task Queue
- Table: `agent_execution_tasks`
- API:
  - `POST /api/v1/agent-runtime/executions/{execution_id}/tasks`
- Queue controls:
  - unique queue position per execution
  - terminal executions reject new queued tasks

### 4) Audit Logs
- Table: `agent_execution_audit_logs`
- API:
  - `GET /api/v1/agent-runtime/executions/{execution_id}/audit-logs`
- Captured events include:
  - execution created
  - task enqueued
  - status updated
  - approval requested/reviewed

### 5) Human Approval
- Table: `agent_execution_approvals`
- API:
  - `POST /api/v1/agent-runtime/executions/{execution_id}/approvals`
  - `PATCH /api/v1/agent-runtime/approvals/{approval_id}`
- Approval flow:
  - request sets execution to `waiting_approval`
  - approve returns execution to `queued`
  - reject moves execution to `cancelled`
