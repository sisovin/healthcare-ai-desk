# M2.1 — Agent Registry Foundation

## Objective
Implement base Agent Registry application contracts over the existing `agent_profiles` schema.

## Inputs from previous milestones
- M1.3 organization security model (JWT org scope + RBAC).
- M1.4 database foundation (`agent_profiles`, `agent_project_assignments`).

## Deliverables
1. API schemas for agent create/update/read/list payloads.
2. Repository/service layer for:
   - create agent profile
   - list agent profiles by organization
   - read profile by id/slug (organization-scoped)
   - update profile details/status
3. Validation rules:
   - unique slug per organization
   - allowed status transitions
   - provider/model field integrity

## Proposed endpoints (organization-scoped)
- `POST /api/v1/agents`
- `GET /api/v1/agents`
- `GET /api/v1/agents/{agent_id}`
- `PATCH /api/v1/agents/{agent_id}`

## Implementation status
Implemented in:
- `app/api/v1/agents.py`
- `app/services/agent_registry.py`
- `app/schemas/agent.py`

Validation tests:
- `tests/test_agent_registry_endpoints.py`
- `tests/test_rbac_permissions.py`
- `tests/test_organization_isolation.py`

## RBAC requirements
- `agent.read`: list/get
- `agent.write`: create/update/status changes

## Test requirements
- Positive CRUD path tests.
- Denial tests for missing/invalid org header.
- Denial tests for insufficient permissions.
- Denial tests for cross-organization access attempts.
