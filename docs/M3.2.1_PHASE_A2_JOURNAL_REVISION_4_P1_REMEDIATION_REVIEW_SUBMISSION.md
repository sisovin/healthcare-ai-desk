# M3.2.1 Phase A.2 — Journal Revision 4 P1 Remediation Submission

**Scope:** review-only source, contract, and offline regression evidence.  
**Execution authorization:** `false`.

## Remediations

This revision addresses two independently reported P1 findings in the
review-only journal. It does not run SQL, Alembic, Docker, MySQL, Redis,
writers, or M3.2.2 workers.

| Finding | Fail-closed correction | Regression evidence |
| --- | --- | --- |
| Existing `.lock` has no `.lock.meta` | `JournalFileLock.acquire()` distinguishes a newly-created fixed-byte lock from an existing one. An existing lock without metadata is ambiguous, releases its OS lock handle, closes it, and raises `JournalViolation`. | `test_existing_lock_without_metadata_fails_closed_and_releases_handle` |
| Reconciled ownership epoch can decrease | `reconcile_prepared()` and `_validate_reconciliation_record()` require `new_epoch > prior_epoch`. This applies both at creation and persistence/reload validation. | `test_reconciliation_requires_a_strictly_later_ownership_epoch_on_creation_and_reload` |

The old ownership must still differ by instance/run identity and reconciliation
must remain tied to the exact prepared step and approval evidence. Strictly
increasing epoch is an additional invariant, not a replacement for those
checks.
