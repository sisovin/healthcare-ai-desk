## Historical epoch monotonicity

Revision 5 closes the defense-in-depth finding from the independent Revision 4
review. A new `PREPARED` ownership epoch must now be greater than every prior
`PREPARED` or `RECONCILED` ownership epoch in the complete journal history.

- `prepare_step()` rejects a proposed epoch at or below the historical maximum.
- `_validate_journal_state()` independently walks all persisted ownership
  records and rejects any non-increasing sequence before persistence/reload.
- Regression covers both direct new-step creation after a completed epoch `5`
  and a forged persisted history that appends epoch `2` after epoch `5`.

This supplements, rather than changes, the Revision 4 requirement that a
reconciliation itself use `new_epoch > prior_epoch`.

## Offline Windows test-environment remediation

The previous file-backed test module used pytest's `tmp_path`, which could fail
under the local sandbox with `WinError 5`. It now uses UUID-scoped flat files
under an explicit local temporary root. `HAD_OFFLINE_TEST_TMP` can override
that root for a restricted Windows TEMP policy. The fixture probes writability
and cleans only known flat test files; it neither uses a database nor creates a
directory tree that requires recursive cleanup.
