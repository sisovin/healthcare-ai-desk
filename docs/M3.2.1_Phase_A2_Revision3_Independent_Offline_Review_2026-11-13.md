## 2. Verified improvements

- Review-only journal schema 4 includes immutable ownership (`epoch`, `instance_id`, `run_nonce`) on PREPARED and final outcomes.
- New-owner reconciliation requires a separate append-only RECONCILED record referencing the prepared step, prior ownership, reviewer ID, approval reference, a 64-character SHA-256 evidence reference, and passing observed checks. Regular actions under a mismatched owner are rejected.
- The first durable write must contain exactly one PREPARED; each subsequent write appends no more than one valid transition. Fault-latched sessions cannot continue after failed mutation/persistence.
- The design remains non-executing and explicitly cannot validate the identity of the external approving reviewer by itself.
- M3.2.2 documentation-level checks confirm the canonical trusted-router, stable logical-handler, workflow-version ordering and M2.5 external-action boundary. These are documentation assertions, not router integration tests.

## 3. Residual findings

### P1-A — Existing lock file with missing metadata is still accepted

**Location:** `JournalFileLock._open_fixed_lock_byte()`, `_read_metadata()`, and `acquire()`.

**Reproduction (offline scratch directory only):** create a fixed-byte `review.json.lock` without a `.lock.meta`, then call `JournalFileLock.acquire()`. The implementation accepted the lock and wrote a fresh `.lock.meta`. This can obscure evidence of an interrupted acquisition where the file was already present.

**Required fix:** carry an explicit `created_new_lock_file` flag from the exclusive `x+b` path. Permit missing sidecar only if the lock byte file was created in the same acquisition. If `r+b` opened a pre-existing lock file and metadata is absent, stop for independent review. Add an offline regression for this exact case.

### P1-B — Reconciliation does not enforce a strictly increasing ownership epoch in persistence validation

**Location:** `_validate_reconciliation_record()` and `reconcile_prepared()`.

**Reproduction (pure memory):** a PREPARED step owned at epoch 5 was RECONCILED with a different owner at epoch 4, and `_validate_journal_state()` accepted the resulting state. The current check only rejects **identical ownership**, not a lower or equal epoch with a new identity. Although `JournalMutation.__enter__()` computes a later epoch for normal sessions, the persisted invariant is not checked independently.

**Required fix:** reject `new_ownership.epoch <= prior_ownership.epoch` in reconciliation record validation and in the reconciliation creation path. Require globally monotonic epochs across persisted histories. Add tests for equal, decreased, and correctly increased epochs; verify rejection on reload and write, not only through session wrappers.
