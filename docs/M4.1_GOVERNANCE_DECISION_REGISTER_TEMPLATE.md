# Healthcare AI Desk — M4.1 Governance Decision Register Template

**Status:** Template only; no decision is approved by this document.
**Execution authorization:** `false`.
**Use:** Complete, review, approve, version, and independently verify each
record before unconditional M4.2 schema-planning entry.

## 1. Record rules

Every record must be stored in version control and contain all required fields:

| Field | Requirement |
| --- | --- |
| `decision_id` | Stable ID from the register below. |
| `status` | `DRAFT`, `IN_REVIEW`, `APPROVED`, `EXPIRED`, `SUPERSEDED`, or `REJECTED`. Only current `APPROVED` qualifies for M4.2. |
| `owner_id` | Accountable role/person/service identity; not a display name alone. |
| `approver_id` | Authorized approving identity, distinct from owner when separation is required. |
| `decision_reference` | Immutable reference to the approved policy/record/change request. |
| `version` / dates | Decision version, approved-at, effective-at, review/expiry date. |
| `scope` | Explicit organization/environment/data classes/providers; no implied wildcard scope. |
| `evidence` | Links/hashes to reviewed evidence, risk assessment, and verification method. |
| `exceptions` | Explicit expiry and compensating controls; no silent exception. |

Missing, expired, mismatched, or unverified values block M4.2. A completed
template is not a decision until the relevant accountable owner and authorized
approver sign/approve it through the organization’s approved process.

## 4. M4.2 entry review checklist

An independent reviewer must verify all items before recording M4.2 planning
entry as accepted:

- [ ] `M4-GOV-01` through `M4-GOV-07` each have `status: APPROVED`.
- [ ] Each has a current owner ID, approver ID, decision reference, scope,
      effective/review dates, and verifiable evidence.
- [ ] M4-GOV-03 confirms M2.5 can enforce Revision 3 atomic egress attempt
      semantics without granting M4 approval authority.
- [ ] M4-GOV-01 confirms actual schema compatibility before any migration
      source or DDL is drafted.
- [ ] M4-GOV-07 confirms synthetic/disposable-only test boundaries; it does
      not authorize shared-environment work.
- [ ] Revision 3 has an independent architecture/security acceptance decision.

Until every item is independently verified, this register remains a planning
artifact and M4.2 is blocked.
