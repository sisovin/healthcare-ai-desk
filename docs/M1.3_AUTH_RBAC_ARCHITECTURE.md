# M1.3 — Authentication, RBAC, and Token Scope Architecture

## Authentication decision

Healthcare AI Desk uses:
- Email + Password
- Argon2id password hashing
- JWT access tokens
- Refresh token rotation/revocation with token hash storage

## Core components

- Security utilities: `app/core/security.py`
- RBAC map: `app/core/rbac.py`
- Access/permission guards: `app/core/dependencies.py`
- Auth routes: `app/api/v1/auth.py`
- Organization scope checks: `app/core/organization_isolation.py`
- Refresh token model: `app/models/refresh_token.py`

## Authentication architecture

1. User authenticates with **email + password**.
2. Passwords are verified with **Argon2id**.
3. Access token (JWT) contains:
   - `sub` (user id)
   - `org` (organization scope)
   - `role` (membership role)
   - `type=access`
4. Refresh token is opaque, stored only as SHA-256 hash in DB.
5. Refresh token rotation:
   - old token revoked (`revoked_at`, `revoked_reason`)
   - new token issued for same organization scope.

## RBAC architecture

Role set:
- `owner`
- `admin`
- `manager`
- `member`
- `viewer`

Permission guard flow:
1. Validate org context from `X-Organization-Id`.
2. Decode JWT and enforce token org == request org.
3. Resolve active membership (`organization_memberships`).
4. Evaluate permission via role-permission map.
5. Deny with `403` on insufficient permission or cross-org scope.

## Token revocation policy by organization scope

- Login and refresh revoke existing active refresh tokens for same `(user_id, organization_id)`.
- Logout revokes only the matching token in the same organization scope.
- Legacy unscoped refresh tokens are marked revoked during migration with reason `legacy_unscoped_token`.

## Migration chain (preserved)

- `20261112_0001` — system settings
- `20261112_0002` — core business schema
- `20261112_0003` — hardening constraints
- `20261112_0004` — refresh token table
- `20261112_0005` — organization-scoped refresh token policy

No destructive reset is required. Existing data and migration history remain intact.

## Security guarantees (current baseline)

- Organization-level data isolation is enforced at request boundary and token boundary.
- Role checks are centralized in dependency guards.
- Token replay risk is reduced through refresh rotation and revocation tracking.
- Historical migration chain is kept intact for auditability and rollback planning.
