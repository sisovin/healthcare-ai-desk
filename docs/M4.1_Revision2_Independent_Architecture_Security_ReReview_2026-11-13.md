## 3. Changes required before unconditional M4.2 schema-planning acceptance

### Finding R2-01 — P1-E exact CAS precondition is weaker than stated (P1)

**Source:** §5.3 says the activation operation compares the *prior active index generation*, but its conceptual predicate is `active_index_generation < :requested_generation`.

**Risk:** The predicate only establishes an ordering inequality, not that the worker observed the exact expected predecessor state. This leaves the hand-off and concurrent-generation contract imprecise; the implementation could activate an unexpectedly skipped or unready generation if other checks are also incomplete.

**Required design correction:** Make the normative CAS bind `expected_prior_active_index_generation` and check equality with the database's current generation (including explicit first-generation/null behavior), together with expected lifecycle, revocation generation, and permitted staging state. Require generation-level readiness/complete receipt evidence before activation; any zero-row CAS or mismatch must preserve a scoped stale/purge disposition. Prove this using out-of-order workers and incomplete-generation fixtures (M4-T04/T05). The supplied SQL is explicitly labeled conceptual; these are design-hardening requirements, not claims that code currently fails.

### Finding R2-02 — P1-C one-use authorization needs an atomic consume contract (P1)

**Source:** §6.2 specifies one-use flag, expiry and final sender verification but does not define the authoritative place and atomic operation that marks a decision/attempt consumed, or what happens on an ambiguous network timeout.

**Risk:** Two concurrent senders or a crash/retry path could reuse the same decision, or transmit a changed payload without a definitive one-use check. Network timeouts cannot in general prove whether an external provider processed a request.

**Required design correction:** Specify an M2.5-owned or equivalently authorized atomic reservation/consumption state keyed by `egress_attempt_id`, hash, provider, model, endpoint and operation. Define `NOT_SENT/CONSUMED/UNCERTAIN`-like semantics without implying exactly-once external delivery. On ambiguous timeouts, do not reuse the decision; a retry needs a fresh exact-payload policy decision and provider idempotency where available. Add concurrent-sender and timeout/retry negative tests to M4-T06. Verify the real M2.5 interface can supply and enforce this decision before implementation.

## 5. Suggested concise text amendments

- **§5.3 CAS:** "Activation succeeds only if the currently active generation equals the event's `expected_prior_active_index_generation` and the requested staged generation has complete, verified receipts and remains eligible under the current lifecycle and revocation generation. A mismatch is a non-activating stale disposition; never substitute `< requested` for the expected-generation equality check."
- **§6.2 one-use:** "A non-local egress decision must be atomically consumed for one exact payload/destination/operation attempt before transmission. A concurrent or repeated consumption is denied. Network-uncertain attempts cannot reuse the consumed decision; any retry requires a fresh evaluation and external idempotency where supported."

These are **reviewer recommendations**, not assertions that the uploaded contract already includes them.
