# M2.4 — Agent Registry Audit & Acceptance

## Objective
Finalize M2 by adding audit visibility, operational checks, and acceptance verification.

## Audit requirements
- Track key events:
  - agent created/updated/status changed
  - assignment created/removed
- Include actor user id, organization id, entity id, timestamp, and action.
- Ensure audit reads are restricted by organization scope.

## Operational requirements
- Deterministic error responses for:
  - permission denied
  - scope mismatch
  - duplicate slug/assignment conflicts
- Backward-compatible migration strategy (no destructive resets).

## Test acceptance suite
1. Unit tests:
   - service-level validation and transition rules
2. API tests:
   - CRUD/assignment happy paths
   - organization/rbac denial paths
3. Security regression:
   - ensure M1.3 auth + org isolation remains intact

## Exit criteria for M2 completion
- All targeted tests pass.
- No cross-organization access path found in API tests.
- Migration chain remains forward-only and data-preserving.
- Documentation updated in `README.md` and M2 docs set.
