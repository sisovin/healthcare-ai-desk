# M2.4 — Agent Runtime Reliability & Observability

## Objective
Harden runtime execution before Supervisor and Multi-Agent Collaboration by improving lifecycle rigor, retry/idempotency reliability, observability, and secure approval workflows.

## Scope delivered

### 1) Execution lifecycle hardening
- Canonical lifecycle:
  - `queued`, `running`, `waiting_approval`, `succeeded`, `failed`, `cancelled`
- Backward compatibility:
  - incoming `completed` is normalized to `succeeded`
- Transition guards enforced in runtime service.

### 2) Reliability controls
- Idempotency and duplicate protection:
  - `idempotency_key` per org+agent execution.
- Retry policy:
  - `max_retries`, `retry_count`, `next_retry_at`
  - explicit retry endpoint for failed/cancelled executions.
- Timeout policy:
  - `timeout_seconds` persisted per execution.

### 3) Task orchestration
- Dependency-aware queueing:
  - `depends_on_task_id`, blocked→pending promotion when dependency succeeds.
- Scheduling:
  - `scheduled_at` support and next-ready task resolver.
- Attempt controls:
  - `attempt_count`, `max_attempts`, task-level error metadata.

### 4) Human approval reliability
- Approval expiry lifecycle:
  - `expires_at`, `expired_at`, status `expired`
- Expiration processing endpoint with audit trail.

### 5) Observability
- Execution telemetry:
  - `duration_ms`, `token_input_count`, `token_output_count`
  - `last_error_code`, `last_error_message`
- Metrics endpoint for runtime monitoring.
- Audit logs for lifecycle, queue, retry, and approval events.

### 6) Security controls
- Organization isolation on all runtime reads/writes.
- Permission enforcement:
  - `agent.execute`, `agent.approve`, `agent.runtime.read`, `audit.read`
- Secret redaction in execution/audit payloads for sensitive tokens/keys/passwords.

### 7) Integration tests
- End-to-end tests cover:
  - idempotent creation
  - retry flow and metrics
  - dependency/scheduling behavior
  - approval expiry and review protection
  - tenant isolation and RBAC denial paths

## Migration & data safety
- New migration extends history forward-only (no reset).
- Existing API routes remain intact.
- Existing agent records are preserved.
