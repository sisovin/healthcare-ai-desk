# M1.2.3 — Schema Hardening

## Objective
Harden core schema constraints for security and operational safety while preserving migration history and existing data.

## Delivered hardening
- `users.password_hash` changed to `NOT NULL`.
- Role/status guardrails enforced with check constraints:
  - `ck_org_memberships_role`
  - `ck_projects_status`
- DB-level timestamp hardening for `updated_at` fields (MySQL `ON UPDATE` behavior at migration level).
- Refresh token scoping hardening:
  - organization-scoped refresh tokens
  - revocation reason tracking
  - scoped indexes for revocation/lookup performance

## Implemented migrations
- `alembic/versions/20261112_0003_security_hardening_constraints.py`
- `alembic/versions/20261112_0005_refresh_tokens_org_scope.py`

## Backward data safety
- Legacy null password hashes are backfilled before `NOT NULL` enforcement.
- Legacy unscoped refresh tokens are revoked (not deleted) with reason `legacy_unscoped_token`.
- No database reset; data retained in-place.

## Validation
- `docker compose exec -T api alembic upgrade head`
- `docker compose exec -T api alembic current`
- `docker compose exec -T api python -m pytest -q tests`
