## Dispatcher lifecycle contract to test

- A single publisher instance claims work with `lease_owner` and `lease_expires_at`; another instance only reclaims an expired lease.
- Startup scans pending and expired processing events. Shutdown stops new lease claims, allows bounded in-flight completion, and leaves unacknowledged work recoverable by lease expiry or Redis pending-entry reclaim.
- Redis Stream consumer acknowledges (`XACK`) only after MySQL side effects and deduplication ledger commit. Idle pending entries are reclaimed with `XAUTOCLAIM` and processed idempotently.

## Ordering policy to test

Conversation-visible messages are ordered by server-owned `sequence_number`. Delivery is at-least-once and may be parallel across conversations. Within a conversation, any state-changing consumer must enforce correlation/state-version preconditions; it must not assume Redis delivery order alone.

## Final-review remediation: end-to-end workflow and publisher fencing — 2026-11-12

### End-to-end durable workflow

`test_m314_end_to_end_conversation_supervisor_approval_outbox_workflow` provides one MySQL-backed workflow proof with a fresh verification session:

```text
Conversation message (PII redacted; state_version 1 → 2)
  → durable conversation.message_created outbox event (no raw patient ID)
  → SupervisorPlan + ConversationTask
  → AgentExecution waiting_approval + M2.5 pending approval
  → independent authorized human approval
  → ConversationTask and AgentExecution both queued
```

The task projection is updated in the same approval-review transaction as the M2.5 execution transition. Supervisor still cannot grant an approval; it only observes the human-authorized result.

### Publisher-fencing hardening

`publish_leased_event` now selects the outbox event `FOR UPDATE` before validating lease ownership and retains that row lock through Redis `XADD` and its MySQL published-state update. This removes the lease-transfer window between an unlocked ownership check and `XADD`.

This does not claim exactly-once publication: a process failure after `XADD` but before MySQL commit can produce at-least-once delivery. The existing unique consumption ledger and consumer idempotency remain the required protection for that deliberate delivery guarantee.
