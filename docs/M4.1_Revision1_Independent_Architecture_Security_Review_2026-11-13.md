## Priority follow-up clarifications (not reversals of the four design-level closures)

### P1-A — Make the SQL visibility predicate unambiguously grouped

§3.2 presently shows `AND candidate.visibility is organization-wide OR candidate.project_id IN ...` without grouping, even though the following prose explicitly mandates parentheses. The authoritative shape must be:

```text
AND (
   (candidate.visibility = organization_wide AND organization_scope_permits)
   OR (candidate.visibility = project_restricted AND candidate.project_id IN permitted_project_ids)
)
AND active_acl_grant_permits
AND effective_agent_assignment_permits_if_applicable
```

All tenant, classification, lifecycle, purpose, legal-hold, and generation predicates remain mandatory **outside** that OR group. Implement explicit SQL and repository negative tests for OR-precedence bypass, organization-wide/ACL bypass, malformed project IDs, and forged tenant inputs (M4-T01).

### P1-B — Define response-finalization consistency and revoke-vs-disclose race

§3.3 requires an immediate post-search MySQL check; M4-T03 also demands denial if ACL/assignment changes before response assembly. Specify a concrete *final disclosure boundary*: authoritative generation/ACL/assignment state is rechecked after result assembly and before emitting chunks/citations or any streamed tokens, with an explicit strategy for mid-stream revocation (stop output, close stream, audit). Define the transaction/read-consistency or generation-check mechanism, and tests for revocation at each asynchronous boundary. Do not rely on cached authorization alone.

### P1-C — Bind M2.5 decisions to the exact outgoing payload and destination

§5 covers operation-specific egress. Add payload/redacted-payload SHA-256, operation ID, destination endpoint/provider/model/region, policy version, caller/purpose, expiry/one-use semantics, and egress attempt ID to the policy-decision contract; re-evaluate after any content, retrieval, redaction or provider change. Define local vs external vector DB and embedding/reranking boundaries (including telemetry and backups) so remote Qdrant or its vector payloads do not silently escape classification rules. Add denied-provider failover, post-redaction mutation, query-embedding, and reranker leakage negatives to M4-T06.

### P1-D — Specify PHI pre-processing quarantine and least-privilege parsing

§2 says classify before extraction but some document/image PHI cannot be detected without parsing. Define an *untrusted quarantine → protected local extraction/OCR → classification/redaction → approval → indexing* pipeline. Extraction/OCR remains private and policy-bound; uncertain/failed results are not indexed. Assert temporary artifacts, OCR logs, debugging traces, and caches cannot hold accessible PHI. This is an implementation detail needed for the stated fail-closed rule.

### P1-E — Define replay, receipt uniqueness and index activation boundaries

For §4/§6, identify composite uniqueness for receipt `(organization_id, document_version_id, chunk_id, embedding_model_version, collection_schema_generation, index_generation)` (or equivalent immutable key), an authoritative `ACTIVE` generation CAS, and stale-write cleanup. Test commit/XACK/retry and revoke-before/after Qdrant upsert, including an old worker writing after a new generation becomes active. Physical stale point existence may be tolerated temporarily only if never accessible via the authorized retrieval path.

### P1-F — Record governance and infrastructure ownership before M4.2

§9 explicitly leaves unresolved: exact MySQL/Alembic head and composite FK types, Qdrant isolation/ACL/TLS/network/backups, classification and M2.5 integration mapping, key management, clinical approval/licensing/jurisdiction, and legal-hold retention owner. Assign reviewer/approver IDs and version-controlled decisions, then separately approve synthetic disposable testing. Clinical reference citations must include effective/expiry/supersession metadata and must not imply patient-specific diagnosis or treatment authorization.
