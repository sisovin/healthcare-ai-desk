## 3. P1 closure findings

### P1-A: Existing fixed-byte lock with absent `.lock.meta`

**Pass.** `JournalFileLock._open_fixed_lock_byte()` returns `(handle, created)`; `acquire()` rejects `not created and previous is None`. Its failure branch attempts to unlock and close the acquired handle. A separate independent Linux sandbox probe using a real existing `.lock` file and no `.lock.meta` raised `JournalViolation`, left `lock._handle` unset, and permitted an independent nonblocking OS lock afterward. The targeted regression also simulates cleanup using a fake handle.

Source: `tools/recovery/m321_step_journal.py`, methods `_open_fixed_lock_byte()` and `acquire()`. Native Windows locking still unverified.

### P1-B: Reconciled ownership epoch decreases

**Pass.** Both `reconcile_prepared()` and `_validate_reconciliation_record()` enforce `new_epoch > prior_epoch` after validating the ownership structure. Independent probes rejected a reconciliation from epoch `5` to `4` and a tampered persisted `RECONCILED` record with epoch `4`, each raising the monotonicity violation. The new regression checks creation and state validation.

Source: `tools/recovery/m321_step_journal.py`, functions `_validate_reconciliation_record()` and `reconcile_prepared()`.

## 4. Additional review-only hardening opportunity (not reopening either original P1)

**Historical epoch monotonicity for a subsequent new `PREPARED`.** An isolated in-memory probe created an initial `PREPARED` at epoch `5`, finalized it, then created another `PREPARED` at epoch `2`. The full `_validate_journal_state()` accepted this history. The normal `JournalMutation` code calculates `max_previous_epoch + 1`, so the canonical mutation path already aims to prevent it. However, the shared persistence validator does not independently enforce monotonically increasing epochs across *all new* `PREPARED` records. Before any future executable runner integration, extend full-history validation to forbid this condition and add a regression test. This is a defense-in-depth recommendation, **not evidence that the two specified Revision 4 remediations failed**.

Also pending: external authentication of independent reconciliation approval, verification of actual snapshot-file bytes at the execution boundary, Windows-native locking/crash/power-loss behavior, and complete broader suite evidence.
