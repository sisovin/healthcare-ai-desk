# M1.2.2 — Core Business Schema

## Objective
Introduce core domain entities required before security/RBAC layers and AI agent workflows.

## Delivered entities
- `organizations`
- `users`
- `organization_memberships`
- `projects`
- `patient_records`

## Implemented artifacts
- Models:
  - `app/models/organization.py`
  - `app/models/user.py`
  - `app/models/organization_membership.py`
  - `app/models/project.py`
  - `app/models/patient_record.py`
- Migration:
  - `alembic/versions/20261112_0002_core_business_schema.py`

## Data integrity
- Foreign keys with explicit `ondelete` behavior.
- Unique constraints for key business identifiers (email, org slug, project slug per org, org-user membership uniqueness, patient external reference per org).
- Indexes on join/filter columns (`organization_id`, `user_id`, `project_id`, `email`).

## Migration policy
- Keeps `20261112_0001` intact.
- Applies `0002` incrementally on top of existing data.

## Validation
- `docker compose exec -T api alembic upgrade head`
- `docker compose exec -T api python -m pytest -q tests`
