# M1.1 API Liveness Troubleshooting

The updated `scripts/verify.ps1`:
- discovers the host port published by Docker Compose;
- uses `127.0.0.1` rather than `localhost`;
- prints the underlying HTTP exception;
- prints container state, API logs, and port mapping on failure;
- prints MySQL/Redis logs if readiness fails.

Run from the repository root:
```powershell
docker compose ps -a
.\scripts\diagnose-api.ps1
.\scripts\verify.ps1
```

Interpretation:
- `had-api` Exited/Restarting: inspect API logs for Python import/configuration errors.
- `had-api` Up but no port mapping: inspect Compose config and startup output.
- API container healthy but host request fails: check host port mapping, firewall/security software, and port collision.
- `docker compose port api 8000` returns a non-8000 host port: the old script may have queried the wrong port if `.env` changed `API_PORT`.
- HTTP 200 on `/health` but 503 on `/ready`: API process is running; inspect MySQL/Redis dependency details.

Never share `.env` contents, passwords, tokens, or patient information.
