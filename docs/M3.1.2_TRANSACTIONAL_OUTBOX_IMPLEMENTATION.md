- Redis Streams `XADD` publishing, `XACK` only after consumer commit, and `XAUTOCLAIM` helper for idle pending-entry recovery.

## Delivery contract

Delivery is **at least once**, never exactly once. Consumers call `consume_event` before acknowledgement; it records consumption in MySQL in the same transaction as the caller-provided side effect. A duplicate event/consumer combination is a no-op. `XACK` is invoked only after that transaction has committed.

Redis outage/restart does not lose the authoritative event: failed publish returns the event to `pending` with a retry time, while MySQL retains the event and lease/retry history. A failed event may be replayed only through the audited operator path.
