## Independent-review request

An independent reviewer should evaluate the following before M4.2 is allowed
to start:

1. **Predicate completeness:** Verify the actual proposed MySQL query design
   cannot widen access through `OR` precedence, organization-wide visibility,
   cache reuse, or missing agent assignment checks.
2. **Race behavior:** Verify revocation/ACL withdrawal at each boundary:
   before search, after Qdrant candidates return, during authoritative fetch,
   immediately before response, before worker write, and after worker write.
3. **Egress policy mapping:** Verify M2.5 exposes all needed decisions for
   query embeddings, document embeddings, reranking, and final LLM context,
   including provider region/retention and denial behavior.
4. **Provenance/rebuild:** Verify the future schema can enforce immutable
   source/version identity, deterministic point identity, collection schema
   generation, and idempotent receipts with composite tenant keys.
5. **Data governance:** Assign accountable owners for clinical review, source
   licensing, redaction/detection exceptions, retention, legal hold, key
   rotation, and incident/audit access.
6. **Testability:** Approve the M4-T01 through M4-T10 matrix and require
   disposable/synthetic fixtures before a test is reported as passed.
